# Безопасность и доступы — прочитать перед началом работы

## Важно: доступы из акта сдачи требуют смены

Акт сдачи сайта (26.06.2026) содержит в открытом (незашифрованном) виде: логин и пароль от `casa24.md/wp-admin` и учётные данные хостинга (email + пароль). Это стандартная практика передачи доступов при сдаче проекта, но раз данные прошли через PDF-документ (вероятно, пересланный по почте/мессенджеру и теперь хранящийся у нескольких людей), правильная гигиена — считать их потенциально скомпрометированными.

**Рекомендация (сделать один раз, до начала активной работы над сайтом):**

1. Сменить пароль администратора `wp-admin`.
2. Сменить пароль от панели хостинга.
3. Включить двухфакторную аутентификацию на обеих панелях, если провайдер это поддерживает.
4. Создать отдельные учётные записи wp-admin для каждого, кто реально работает с сайтом (dev-agent-исполнитель, координатор), вместо одного общего `admin`-логина — так в логах видно, кто что менял.
5. Новые пароли сохранить **только** в менеджере паролей с общим доступом для команды (например, Bitwarden или 1Password с shared vault) — не в чатах, не в файлах на рабочем столе, не в этом репозитории.

## Правила для этого репозитория

- Пароли, ключи API (платёжная система, Telegram-бот), файлы `wp-config.php` — **никогда не коммитятся**. `.gitignore` уже настроен на основные паттерны (`*password*`, `*secret*`, `*credentials*`, `wp-config.php`), но это не гарантия — проверяйте diff перед коммитом.
- Если для автоматизации деплоя в будущем понадобится CI/CD (например, GitHub Actions для авто-деплоя на хостинг) — секреты хранить в GitHub Actions Secrets проекта, не в коде.
- **Репозиторий на GitHub (`casa24-site`) — Public**, по осознанному решению владельца (изначально рекомендовалось Private). Значит: правило «пароли/ключи не коммитятся» соблюдать особенно строго — здесь нет второго рубежа защиты в виде закрытого доступа. Если в какой-то момент решение поменяется — Settings → Danger Zone → Change visibility → Private, без потери файлов и истории.

## Кто имеет доступ

Зафиксировать здесь (обновлять по факту), кто реально имеет пароли от wp-admin и хостинга — минимальный круг, а не «все причастные»:

- Владелец/координатор — да.
- dev-agent (исполнитель разработки) — да, для деплоя.
- Остальные роли (content, seo, marketing, ops) — доступ только к своим системам (WooCommerce-интерфейс с ограниченной ролью, рекламные кабинеты, Telegram), не к полному wp-admin/хостингу.

## Другие ключи (не из акта)

- `OPENROUTER_API_KEY` (используется media-agent для AI-редактирования фото товаров через скил `generate-image`) — риск ниже, чем у wp-admin/хостинга, но правило то же: только в `.env` у media-agent, никогда в репозитории и в чатах. Ключ привязан к платному аккаунту OpenRouter — при утечке кто угодно тратит чужой бюджет, не только смотрит данные.

## Если пароли всё же были где-то засвечены до наведения порядка

Проверить логи входов в wp-admin и хостинг-панель на подозрительную активность за период с даты акта (26.06.2026) по дату смены паролей. Если сайт использует WooCommerce с сохранёнными платёжными данными — уточнить у платёжного провайдера, не требуется ли дополнительная проверка.
