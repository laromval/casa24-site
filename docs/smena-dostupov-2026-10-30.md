# Смена паролей и ключей casa24.md — 30.10.2026

Основание: №24 в `docs/priorities.md`. Полный бэкап `wp-admin.zip` вместе с `wp-config.php` около трёх месяцев лежал в открытом доступе (убран 25.10.2026). Последний вход в cPanel был с IP 83.218.209.99, вероятно подрядчика. Пароль администратора WordPress уже сменён 26.10.2026.

**Правила.** Пароли придумывает и вводит владелец. В чат, в репозиторий и в этот файл они не попадают, хранятся только в менеджере паролей. Команды на проде Claude выполняет только после «да» владельца на каждый шаг. В панелях идём по одному шагу: владелец присылает скриншот или ответ, потом следующий шаг.

**Когда.** Вечером, когда заказов мало. Займёт около 40–60 минут. Сайт не отключается: пароль БД меняем через нового пользователя, поэтому простоя нет. После смены ключей всех выкинет из аккаунтов.

## Шаг 0. Подготовка (владелец)

- Открыт менеджер паролей, туда сохраняем каждый новый пароль сразу после создания.
- Под рукой вход в клиентскую зону TopHost, в cPanel и в wp-admin.
- Телефон рядом, если TopHost или cPanel спросят код.

## Шаг 1. Резервная копия и разведка (Claude, SSH, только чтение и бэкап)

1. Скопировать `wp-config.php` прода и staging в `~/backups/rotation-20261030/` и сделать дамп БД туда же.
2. Выяснить, не показывая значений:
   - какие `DB_NAME` и `DB_USER` у прода и у staging, и не один ли у них пользователь БД;
   - есть ли пароль БД где-то ещё, кроме `wp-config.php`: скрипты, `~/.my.cnf`, crontab;
   - есть ли внутри `~/wp-admin.zip` дамп базы (`*.sql`). От этого зависит шаг 5;
   - есть ли у пользователей WordPress пароли приложений (Application Passwords) и ключи REST API WooCommerce, кому они выданы и когда последний раз использовались.

## Шаг 2. Пароль базы данных, без простоя (владелец в cPanel и Claude по SSH)

Старого пользователя БД мы не трогаем, пока сайт не заработает с новым.

1. cPanel → «Базы данных MySQL» → «Добавить нового пользователя», например `casamd_web30`. Пароль сгенерировать там же («Генератор паролей») и сохранить в менеджер.
2. Там же «Добавить пользователя в базу данных»: новый пользователь, база прода, **ALL PRIVILEGES**.
3. cPanel → «Диспетчер файлов» → `public_html/wp-config.php` → «Редактировать»: заменить `DB_USER` и `DB_PASSWORD` на новые и сохранить.
4. Claude проверяет: главная RU/RO отвечает 200, `wp db check` проходит, вход в wp-admin работает.
5. Если что-то не так, вернуть в `wp-config.php` старые значения из копии шага 1. Старый пользователь ещё жив, поэтому сайт сразу оживёт.
6. Когда всё работает: cPanel → «Базы данных MySQL» → «Текущие пользователи» → удалить **старого** пользователя БД.
7. Если staging использует того же пользователя (это выяснится на шаге 1), повторить пункты 1–5 для staging **до** пункта 6.

## Шаг 3. Ключи и соли WordPress (Claude по SSH)

1. Прод: `wp config shuffle-salts`. Новые ключи генерируются на сервере, их никто не видит.
2. Staging (копия сделана 27.09, ключи достались от прода): то же самое.
3. Последствия: все пользователи, включая владельца, выйдут из аккаунтов. Корзины гостей могут обнулиться, поэтому делаем вечером. Владелец входит в wp-admin заново.

## Шаг 4. Пароль cPanel и ревизия доступов (владелец)

1. Клиентская зона TopHost или cPanel → сменить пароль, сохранить в менеджер.
2. Включить двухфакторный вход в cPanel («Безопасность» → «Двухфакторная аутентификация»), если он есть у TopHost.
3. cPanel → «Доступ по SSH» → «Управление ключами SSH»: должен остаться только `claude-casa24`, всё остальное удалить.
4. cPanel → «Учётные записи FTP»: удалить учётки подрядчика и все, которые вы не узнаёте.
5. cPanel → «Управление маркерами API» (API Tokens): удалить всё незнакомое.
6. «Последний вход» после смены пароля должен показывать ваш IP.

## Шаг 5. Ключи сервисов (только если в архиве был дамп БД или шаг 1 нашёл лишние доступы)

Если в `wp-admin.zip` лежал дамп базы, утекли и данные, которые плагины хранят в БД. Тогда нужно сменить:

- ключи maib (кабинет мерчанта maib → новые ключи → WooCommerce → Платежи → maib);
- токен Telegram-бота уведомлений (@BotFather → `/revoke` → новый токен в TelSender);
- логин и пароль обмена с 1С (настройки модуля itgalaxy на сайте **и** в 1С одновременно, иначе выгрузка встанет);
- ключи REST API WooCommerce и пароли приложений: отозвать все, которые выдавались подрядчику.

Дамп в архиве содержит ещё и персональные данные покупателей. Тогда это вопрос к юристу по Закону № 195/2024: возможно, нужно уведомлять CNPDCP (см. №43, порядок при утечке).
