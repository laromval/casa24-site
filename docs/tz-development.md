# ТЗ на разработку и доработку сайта casa24.md

## 1. Цель

Привести уже работающий интернет-магазин casa24.md в состояние, которому покупатель доверяет и в котором нет ошибок, мешающих продажам, и подготовить техническую базу для дальнейшего продвижения. Это не переработка сайта с нуля — сайт принят по акту 26.06.2026 и функционально полон (см. `docs/site-reference.md`); задача — исправление и системное сопровождение.

## 2. Текущее состояние (входные данные)

- Стек: WordPress + WooCommerce, тема Glozin, конструктор Elementor 4.0.9, мультиязычность WPML (RU/RO).
- Разработчик: «CLICK WEB DESIGN» SRL, договор №21/05-26A от 21.05.2026, акт сдачи от 26.06.2026, сумма 32 000 MDL без НДС.
- Аудит сайта проведён 13.09.2026, полный список находок — `docs/priorities.md`.
- Проект будет вестись через GitHub (эта репозиторий), боевой сайт — на отдельном хостинге (реквизиты — только в менеджере паролей, не здесь, см. `docs/security-notes.md`).

## 3. Состав работ

### Этап 1 — критичные исправления (P0)

1. **Брендинг.** Заменить логотип и favicon «Larom VAL» на актуальный бренд (Casa24 / Meșterul Casei) во всех местах: шапка, favicon-файл (`cropped-Laromval-ICO-32x32.webp` → новый), проверить title и подвал на единообразие названия.
2. **Ошибка цены.** Исправить цену товара «Дверь межкомнатная Model R14» (сейчас 1,00 MDL) на рыночную (аналоги — 2 100–2 900 MDL). Провести ревизию всего каталога на похожие аномалии (content-agent + qa-agent).
3. **SEO-метаданные.** Добавить meta description на главной и в ключевых категориях (RU и RO), добавить Open Graph теги (og:title, og:description, og:image).
4. **Логика блоков «Топ продаж» / «Популярные товары».** Сейчас показывают идентичный список — развести по разным критериям (продажи vs просмотры) или ручному подбору.

### Этап 2 — важные исправления (P1)

5. Alt-теги для всех изображений товаров и баннеров (сейчас 19 из 53 без alt на главной).
6. Устранение дублирования блоков категорий и отзывов в HTML (проверить настройки карусели Elementor/Swiper — вероятно, инфинити-луп без корректной разметки для скринридеров).
7. Долив перевода на румынскую версию — в первую очередь блок «Recenzii ale clienților», где сейчас русские тексты.
8. Отключить в sitemap раздел `wp-sitemap-users` (не светить логины/авторов).
9. Причесать названия товаров: убрать транслит («polotno oreh» → «орех»), лишние символы, опечатки («металичческая» → «металлическая», «Сверло по металлу 5555555»).

### Этап 3 — по мере ресурсов (P2)

10. Ревизия плагинов — объединить/отключить неиспользуемую функциональность (сравнение, wishlist, попапы, каунтдауны), снизить число запросов (сейчас ~130+, ~2 МБ, 60 JS-файлов на главной).
11. Единая предсказуемая структура языковых URL для RO/RU (сейчас hreflang объявляет `/ro/`, а реальные адреса расходятся) — устранить риск дублей в индексе Google.
12. Ускорение TTFB (сейчас ~700 мс): кэширование страниц, PHP OPcache, оптимизация БД WooCommerce, при необходимости — более быстрый тариф хостинга.
13. Одна директива `User-agent: *` в robots.txt вместо двух одинаковых.

## 4. Технические требования

- Все изменения — через ветки в этом репозитории (`feature/*`, `fix/*`), см. `docs/workflow-git.md`. Прямые правки в проде в обход процесса — не допускаются, кроме экстренных hotfix с последующим оформлением задним числом.
- Перед каждым релизом — прогон чек-листа qa-agent.
- Изменения, влияющие на производительность (этап 3, п.10, 12) — сопровождать замерами PageSpeed Insights до/после.
- Секреты (пароли, ключи API оплаты, Telegram-бот токен) — только в менеджере паролей/переменных окружения на сервере, никогда в git.

## 5. Критерии приёмки

- На всех страницах сайта — единый бренд, без упоминаний «Larom VAL».
- Ни одного товара с ценой, отличающейся от рыночной более чем в 2 раза без явного обоснования (акция/распродажа с пометкой).
- Meta description и OG-теги — на всех страницах категорий верхнего уровня и на главной.
- RU и RO версии не содержат текста на другом языке в пользовательских блоках.
- PageSpeed (мобильный) — заметное улучшение относительно замера на момент аудита (базовая метрика фиксируется перед этапом 3).

## 6. Роли

Разработка — dev-agent, контент и цены — content-agent, метатеги/технический SEO — seo-agent совместно с dev-agent, проверка перед релизом — qa-agent. Координатор утверждает переход между этапами и подтверждает выкладку на хостинг.

## 7. Сроки

Этап 1 — в приоритете, без него не имеет смысла запускать продвижение (см. `docs/tz-promotion.md`). Этапы 2–3 — по мере ресурсов команды; конкретные даты фиксируются координатором в `docs/priorities.md` по мере планирования спринтов.
