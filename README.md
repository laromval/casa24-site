# Casa24 — оркестратор проекта

Репозиторий для управления разработкой и продвижением интернет-магазина строительных материалов **casa24.md**. Здесь хранится не код WordPress-сайта целиком, а «мозг» проекта: роли агентов, технические задания, правила процесса и рабочие документы — то, что должно быть доступно с любого компьютера команды.

## С чего начать

1. Прочитать `CLAUDE.md` — общий контекст проекта, приоритеты, правила координации.
2. Прочитать `docs/security-notes.md` — **обязательно, до начала любой работы** (в акте сдачи сайта обнаружены пароли в открытом виде, их нужно сменить).
3. Открыть репозиторий в Claude Code / Cowork — файлы из `.claude/agents/` автоматически становятся доступны как роли-субагенты (через инструмент Agent, `subagent_type`).

## Почему GitHub

Команда работает с разных компьютеров — GitHub даёт общую версию правды: одну и ту же структуру приоритетов, ролей и ТЗ видят все, история изменений сохраняется, а выкладка на боевой хостинг casa24.md происходит осознанно — только после того как изменения смержены в `main` и проверены (см. `docs/workflow-git.md`), а не как попало через FTP с разных машин.

## Как этот репозиторий оказался на GitHub

Проект опубликован не как новый репозиторий, а переиспользованием существующего аккаунта GitHub: старый репозиторий **«ВНЕ ШКОЛЫ»** (не связанный с Casa24 школьный проект, не обновлялся с 2021 года) был переименован в **`casa24-site`**, его прежнее содержимое заменено на этот оркестратор.

Шаги, которые для этого потребовались (сделано вручную владельцем аккаунта, не автоматически):

```bash
# 1. На github.com: репозиторий «ВНЕ ШКОЛЫ» → Settings → Repository name → casa24-site → Rename

# 2. Локально — клонировать переименованный репозиторий (сохраняет его историю):
git clone https://github.com/<ваш-логин>/casa24-site.git
cd casa24-site

# 3. Убрать старое содержимое (кроме .git — историю не трогаем):
git rm -rf .

# 4. Скопировать сюда файлы оркестратора (CLAUDE.md, README.md, .claude/, docs/, .gitignore)
#    из распакованного casa24-orchestrator.zip

# 5. Закоммитить замену и отправить на GitHub:
git add -A
git commit -m "Заменили старый проект оркестратором Casa24"
git push

# 6. Дальше — рабочая ветка:
git checkout -b dev
git push -u origin dev
```

Так старая история репозитория не стирается (в отличие от `push --force`) — просто добавляется коммит, который заменяет содержимое. Дальше — по одной ветке `feature/...` или `fix/...` на задачу, Pull Request в `dev`, ревью, и уже потом релиз в `main` → выкладка на хостинг по чек-листу из `docs/workflow-git.md`.

**Видимость репозитория:** по решению владельца оставлена **Public** (изначально было рекомендовано Private — в репозитории есть находки аудита по уязвимостям сайта и внутренняя бизнес-информация). Раз выбрано Public — дополнительно внимательно: не добавлять сюда ничего чувствительнее того, что уже описано в `docs/security-notes.md`, и периодически напоминать себе, что содержимое видно всем в интернете.
